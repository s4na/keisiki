# 在庫確保の Ruby 実装と Lean 4 の照合

初回の確保で在庫を要求数量分だけ減らし、予約を１件作る。同じ ID と数量で再送されたら、初回に作った予約を返し、在庫も予約も書き換えない。初回コミットの応答が失われた場合の再送をこの契約で評価する。

## 固定したモデル

要求した ID に着目し、状態を残在庫の整数と、その ID の予約数量の有無で表す。`Reservation.lean` の `contract` が、在庫の値、返す予約、発行する書き込みについて次の規則を定義する。

| 開始状態 | 終了状態と結果 |
| --- | --- |
| 予約なし、在庫が数量以上 | 在庫を１回減算し、予約を１件作成して返す |
| 予約なし、在庫が数量未満 | 競合を返す。書き込みなし |
| 同じ ID、同じ数量 | 既存の予約を返す。書き込みなし |
| 同じ ID、異なる数量 | 競合を返す。書き込みなし |

`accepted_matches_contract` は、照合に合格した命令がモデルと同じ結果になることを、すべてのモデル状態と整数について証明する。`accepted_first_and_retry` は、十分な在庫がある状態からの初回の書き込みが在庫更新１回と予約作成１回であり、コミット結果を入力にした同じ ID・数量の再送で書き込みが空になることを証明する。

## Ruby ソースとの対応

照合器は候補を実行せず、Prism で Ruby ファイル全体をパースする。対応する構文は `bin/check-reserve-stock` のテンプレートに記載している。クラスとメソッド、引数とローカル変数の束縛、トランザクション内での在庫行ロックと予約検索、ガードの位置、更新、予約の作成条件、作成時の ID・在庫 ID・数量、処理順を AST 全体で確認する。字句の位置だけが変わるような整形は受理できる。

独立に変化できる構文は下表の４箇所で、組み合わせは最大48通り。ASCII の16,384バイト以下の入力を扱う。

| Ruby の箇所 | 対応する式 | モデル適合時の値 |
| --- | --- | --- |
| 既存予約の数量を比較する演算子 | `!=`、`==` | `different` |
| 在庫更新を実行する述語 | `reservation.nil?`、`reservation.nil?()`、`!reservation`、`!reservation.nil?`、`true`、`false` | `missing` |
| 残在庫と要求数量を比較する演算子 | `<`、`<=` | `less` |
| 更新値を計算する演算子 | `-`、`+` | `subtract` |

一致する AST の４項目を Lean に渡し、Lean は型付きの `Program` に読み込む。Lean が `accepts` で判定するのは `Program` と固定モデルに対応する `reference` の等しさであり、この等しさが証明の適用条件になる。固定 Ruby ファイルのハッシュは CI で資料の来歴確認に使う。操作者が渡す Ruby ファイルの判定には AST と Lean の比較を使う。

Ruby から命令への対応付けと、Rails および DB の呼び出しに対応する以下の前提は、人がレビューする。Lean はその前提の下で状態遷移と書き込みを証明する。

- `Stock.lock.find(1)` は対象在庫１行をロックして取得する。`Reservation.find_by` は要求 ID の確定済み予約か `nil` を返し、返ったレコードは真とみなされる。数量は整数で、比較、算術、`nil?`、否定は標準の動作をする。
- `update!` と `create!` は指定された行と値だけを書き込む。Ruby のクラス・メソッド解決、Active Record のコールバック、DB トリガーなどが別の副作用を追加しない。
- トランザクションは正常時に確定し、`Conflict` はロールバックされる。再送は初回のコミット後に同じ ID と数量で発生する。HTTP、DB 障害、任意の並行実行はこのモデルの範囲外。

## 実行

Ruby 4.0.9 と PATH 上の Lean 4.36.0 を用意する。Elan を使う場合、照合器はこのディレクトリの `lean-toolchain` を使う。Rails や DB は不要。

```sh
bin/check-reserve-stock PATH_TO_RUBY_SOURCE
bin/check-reserve-stock experiments/independent-lean/fixtures/reserve_stock.rb
```

| 終了コード | 出力 | 判定 |
| --- | --- | --- |
| 0 | `VERIFIED` | 対応する命令が Lean の照合に合格 |
| 1 | `MISMATCH` | 構文は対象内だが対応する命令が固定モデルと不一致 |
| 2 | `UNSUPPORTED` | 対象外の構文や入力 |
| 2 | `ERROR` | 読み込み、環境、証明の検査などで実行エラー |

リポジトリのコミット `1b67c63b8406715bfe4112b2a5ae8d4ef1200575` の `example/app/services/reserve_stock.rb` を、内容を変えず比較用に収録した。GitHub Actions はこのファイル、等価な nil ガード、モデルに反する演算と条件、対象外の束縛と書き込み、入力の読み込みエラーを同じ CLI で確認する。固定版と対照例で観測した終了コードは Actions のジョブサマリーに残る。
