# Ruby ソースから在庫更新の証明を生成する実験

CRuby 4.0.9 と Lean 4.36.0 を PATH に用意して、リポジトリのルートで実行する。

```sh
bin/check-reserve-stock experiments/source-generation/fixtures/reserve_stock.rb
```

`fixtures/reserve_stock.rb` は `1b67c63b8406715bfe4112b2a5ae8d4ef1200575` の `example/app/services/reserve_stock.rb` のバイト列をそのまま収録したもの。CLI は指定ファイルを Ripper で解析し、ソースを Ruby としてロードせずに Lean を生成する。入力や生成物の SHA-256 は来歴と再現性を照合するために記録する。

## 対応する Ruby の範囲

クラスとメソッドの定義、トランザクション、ロック付きの在庫取得、予約取得、数量が違う場合の例外、更新と予約作成の順序を構文木で照合する。構文木のうち、在庫更新を選ぶ条件、在庫不足を検出する条件、更新値、`debit_stock?` の式を変換する。

条件式では予約の有無、真偽値と `nil`、否定、論理積・論理和を扱う。トランザクション内の条件では `debit_stock?(reservation)` の呼び出し、および現在庫、要求数量、整数リテラル `0`・`1` の比較も扱う。更新値は現在庫、要求数量、`0`・`1` の加減算に限定する。括弧は対応する単一の式を囲める。命令の追加や順序変更、対応外の呼び出しや演算は入力を対象外にする。

## Lean が検査する性質

`p1_stock_debit` は生成された処理結果と仕様の一致を、すべての整数の現在庫・要求数量と、予約なしまたは任意の整数数量の既存予約について証明する。結果には予約の新規作成・再利用・競合と、在庫への書き込みの有無と値を含める。

- 予約がなく在庫が足りる場合は、一度だけ `現在庫 - 要求数量` を書き込み、予約を作成する。
- 同じ ID で数量が同じ場合は、在庫に書き込まず既存予約を再利用する。
- 同じ ID で数量が異なる場合、または予約がなく在庫が足りない場合は、競合として終了する。

Lean に渡すモデルは次の Ruby・Rails の契約を前提とする。

- 数量は Ruby の整数で、算術・比較・真偽判定・`nil?` は通常の意味を持つ。対象メソッドや定数の外部での上書きは対象外とする。
- `find_by` は要求 ID に対応する予約か `nil` を返し、属性読み取りは副作用のない値取得とする。
- 在庫行が存在し、`Stock.lock.find(1)` とトランザクションが対象在庫への操作を直列化し、コミットされた予約が再試行で見えることを仮定する。
- `update!` と `create!` は指定属性で永続化し、トランザクションは原子的に完了することを仮定する。DB の制約、型変換、コールバック、例外時のロールバック、Rails や DB の設定と並行実行は個別の検証対象になる。

## 結果と CI

| 終了値 | JSON の `status` | 意味 |
| --- | --- | --- |
| 0 | `proved` | 生成モデルと仕様の一致の定理を Lean が検査した |
| 1 | `property_failed` | 生成モデルと仕様が異なる反例の存在を Lean が検査した |
| 2 | `unsupported` | 構文または処理順が変換対象外 |
| 2 | `execution_error` | 入力やツールの障害、または Lean で証明も反例も確定しなかった |

反例探索は在庫・要求数量を `-3..4` とし、各組で予約なし・数量一致・数量不一致の入力を調べる。この範囲には、現在庫・要求数量の `0`・`1` に対する大小関係と相互の順序ごとに、更新値の一次式の違いを識別できる点がある。成功時の定理はこの有限集合に限定されない。

標準出力に一行の JSON を出す。`KEISIKI_LEAN_OUTPUT` にファイルパスを指定すると、終了値 0 または 1 を返す際に Lean が検査したソースを書き出す。GitHub Actions は固定の入力、同値な別実装、在庫更新と再試行の反例、対象外の入力、入力エラーを検査し、生成した Lean と JSON を成果物に保存する。同じ入力の二回の独立した実行では、Lean と JSON のバイト列がそれぞれ一致することを確認する。
