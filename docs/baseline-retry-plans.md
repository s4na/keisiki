# 基準方式の再送入力

`baseline-pbt` は、固定シードから、正常に完了できる初回要求と同一要求の再送の組を生成する。CI は Ruby 4.0.9 でシード 20261125・64 試行を生成し、同じ指定から出力を完全に再現できることと、シードを 20261126 に変えたときに操作列が変わることを検証する。生成した操作列では初期在庫、予約 ID、数量、応答喪失の指定、再送回数を変える。

```sh
bin/baseline-retry-plans 20261125 64 > plans.json
```

JSON の `cases` は指定した試行数ぶんの入力で、`reference_case` は共通課題の在庫２個・数量１個・応答喪失後に１回再送する入力。参照ケースは試行数に含めない。`attempts` の先頭が初回要求で、２件目以降が再送。各ケースは予約が空の状態から開始し、全リクエストで ID と数量を保持する。

各試行の実行時は Rails の HTTP リクエストに `request` を渡す。`drop_after_commit` は初回要求がコミットされ、別接続から確定を観測した後にテストハーネスが応答を破棄する指定。観測した応答喪失は実行履歴へ別途記録し、指定どおりに観測できなかった試行は実行エラーとして扱う。各要求の応答と実 DB の状態は共通の履歴チェックに渡す。この接続、検出の計測、失敗した操作列の縮小は、Rails/PostgreSQL と履歴チェックが main に揃ってから追加する。今回の CI は入力の再現性と妥当性を検証し、検出結果を「対象外」として記録する。
